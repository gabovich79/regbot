# RegBot Golden Set — Retrieval Evaluation

מה מודדים כאן: כמה טוב ה־retrieval מוציא את המסמכים הנכונים, **לפי דירוג**, לא
רק "נמצא/לא נמצא". המדדים: Recall@k, Precision@k, MRR, MAP.

## הרצה

מריצים מה־Render Shell אחרי deploy (הסקריפט שולח embedding queries אבל לא קורא
ל־Gemini ולא משנה את SQLite):

```bash
python scripts/run_retrieval_evaluation.py --top-k 20
```

## סכמת case

כל שורה ב־`retrieval_cases.jsonl` היא JSON אחד:

```json
{
  "id": "management-fees",
  "category": "exact-reference | semantic | multi-document",
  "question": "כמה דמי ניהול מותר לגבות מעמית?",
  "relevant_documents": ["חוזר גמל 2016-9-8 דמי ניהול"],
  "distractor_documents": ["חוזר גמל 2019-9-14 גילוי עלות שנתית צפויה"]
}
```

שדות:

| שדה | חובה | משמעות |
|---|---|---|
| `id` | כן | מזהה יציב (לא משנה מה, רק לא מתנגש) |
| `question` | כן | שאלה בשפה טבעית, כמו שעמית אמיתי ישאל |
| `relevant_documents` | כן | מסמכים שחייבים לצוץ בתוצאות. לפחות אחד |
| `distractor_documents` | לא | מסמכים שאסור לצוץ — הכי חשובים כשיש ״קרוב אבל לא״ |
| `category` | לא | תיעוד בלבד |

### איך מזכים מסמך רלוונטי

כל ערך ב־`relevant_documents` / `distractor_documents` מותאם למסמך לפי:
1. **source_ref** (URL / שם קובץ) — התאמה מדויקת, הכי יציבה. עדיף להשתמש בזה.
2. **כותרת** — התאמה מדויקת, או תת-מחרוזת (הכותרת הקצרה `חוזר גמל 2020-9-2`
   תתאים לכותרת הארוכה `חוזר גמל 2020-9-2 העברת כספים`).

## מהו distractor טוב

Distractor טוב הוא מסמך שקרוב לשאלה אבל לא עונה עליה. דוגמה: שאלה על
**שיעור** דמי ניהול צריכה להחזיר את חוזר דמי הניהול, לא את חוזר גילוי העלות
השנתית — שניהם עוסקים בכסף, אבל רק אחד עונה. זה מה שתופס retrieval ששולף
"בערך קשור".

## הוספת שאלות אמיתיות

הערך האמיתי של הסט הזה מגיע מהשאלות שאתה באמת שואל בעבודה. כשיש לך שאלה
שהבוט ענה עליה נכון (או לא נכון), תוסיף אותה כאן:

1. כתוב את השאלה בדיוק כמו ששאלת.
2. תן ב־`relevant_documents` את המסמך/מסמכים שהתשובה הייתה צריכה להסתמך עליהם.
3. אם הבוט הביא מסמך לא נכון — שים אותו ב־`distractor_documents`.
4. הרץ שוב את הסקריפט וודא שהמדדים השתפרו (או נשארו).

המטרה: לגדל סט של 30–50 שאלות אמיתיות, ואז כל שינוי בצנרת (chunking, ranking,
embedding) נמדד מול אותו סט במקום לנחש.
